# Security

music-skill runs on your own machine, with your rights. Its scripts read the project, MIDI and audio files they are given and write their results to the folders they are given. Renders, reviews, analyses, revisions and configurations go to new paths and never overwrite earlier ones.

- **Input files are data.** Projects, MIDI and audio files, bank and split specs, and render, round, audition and cache folders are read within limits, validated and never executed, also when they come from someone else. MIDI is read with size and event limits; project files are validated against fixed ranges; a name taken from a file is checked before it becomes part of a path.
- **The configuration file is not data.** It names the programs that run (FluidSynth, FFmpeg, the Surge XT plugin, the folder pedalboard is loaded from) and the banks they read. Its hashes show that those files have not changed since it was written, not who made them. Use the configuration the setup wrote on your machine, or one you wrote yourself: a configuration that arrived with a project, an archive or a download can name any program on your disk or beside it, and running a command with it runs that program. The same holds for a runtime folder someone else filled.
- **Your folders are for one account.** The work folders, the cache and the runtime are checked before anything is written or removed there, but those checks are not defended against another account changing the folder at the same moment. Do not share them writable with an account you do not trust.
- **Links are not followed.** A folder given as a link, or found as one where the tools write (a render's output or cache, the render inside a round, a cache entry or its lock, a folder of the runtime), is refused; a render or cache folder holding a link is not read.
- **Downloads** happen only during setup, over HTTPS, from a fixed list of hosts: GitHub (releases, raw files, and the API for a source build's file list), the University of Iowa's sample site (only when its banks are built from source) and PyPI's file host (the pedalboard wheel). Every redirect is checked against that list before it is followed. Every tool, bank, archive, sample, patch and wheel must match the size and SHA-256 (or git hash) pinned in the skill's lock files: a download that does not match is never kept, and a cached file that does not match is set aside and fetched again, or stops the setup, which names it. A source build's file list is not pinned itself: it must name the pinned commit, and every sample it leads to is checked against its pinned hash. Archives are listed before extraction, and members with absolute paths, `..` or links are refused; a .7z, which tar or 7-Zip unpacks, goes into a new private folder first, and nothing is installed from it if a link is found there.
- **External programs** are FluidSynth, FFmpeg, pip (which installs the pinned pedalboard wheel from the downloaded file, without going online), tar or 7-Zip (to unpack a FreePats .7z, only when the release cannot be reached) and the skill's own Surge XT host (`scripts/surge_host.py`, which loads pedalboard and the Surge XT plugin), all started without a shell. FFmpeg receives only local audio files (WAV; the MP3 and Ogg files a render has just written, to check them; FLAC recordings when a bank is built from them) and filter settings built from numbers; filter text is never taken from a project.

## Reporting a vulnerability

If you find a way to make a script do something it should not, such as writing outside the paths it was given, fetching from another host or running code from an input file, please report it privately: on this repository, open **Security**, then **Report a vulnerability** (or go straight to https://github.com/owoevan-dev/music-skill/security/advisories/new). Please don't open a public issue for it.

A fix goes into the next release, and the changelog says what was fixed.

Ordinary bugs are welcome as [issues](https://github.com/owoevan-dev/music-skill/issues).
